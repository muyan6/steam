# P2P 对端延迟与第二轮修复

## 前端效果

联机面板的「连接对端与延迟」列表按对端显示心跳 **RTT / ms**，每 3 秒读取更新：

- 有新鲜、可归属的样本：显示如 `37 ms`，按延迟区间使用绿/黄/红文字。
- 没有样本：显示「未采样」，不显示伪造的 0 ms。
- 30 秒未更新或日志时间在未来：显示「已过期」，旧数字不冒充当前延迟。
- 只有本地端口接入记录、没有对应身份：保留接入记录，但不推断属于哪个玩家，不借用其他人的延迟。

这不是游戏内 Ping，也不是服务器探测延迟。只有对端心跳行才参与显示；握手总耗时、服务器 `synctime rtt=`、未知隧道 ID 一律不当作玩家 RTT。

## 日志格式与身份关联

核对的上游源码：

- [隧道心跳 RTT，源码固定版本](https://github.com/openp2p-cn/openp2p/blob/21b99a7cea5d87c2796ca91851b74e6ae0850020/core/p2ptunnel.go)。直连使用 `tunnel ID read tunnel heartbeat ack, rtt=Nms`。
- [中继心跳，源码固定版本](https://github.com/openp2p-cn/openp2p/blob/21b99a7cea5d87c2796ca91851b74e6ae0850020/core/p2papp.go)。中继使用 `appid:N relay heartbeat I store rtt N`，表示 App 对端心跳往返。
- [日志级别定义](https://github.com/openp2p-cn/openp2p/blob/21b99a7cea5d87c2796ca91851b74e6ae0850020/core/log.go)。心跳 RTT 行位于 Dev 等级，值为 -1。

解析器先关联 `addApp` 的 App 名称与节点，再通过 `appid`、`buildDirectTunnel ... use tid` 建立映射；支持数字 App 名称和中文节点。裸 `rtt=` 没有身份与语义保证，不使用邻近日志猜测。

运行中增量读取日志，保留有界映射；日志轮转不导致玩家与隧道的对应关系消失。发动机初始化事件清空上一会话；断开后迟到的心跳不重新激活旧对端。单次读取不超过 1 MiB，映射和玩家数量均有上限。

本机此前保存的 OpenP2P v3.25.11 日志没有玩家心跳 RTT 样本，因此没有把本机数据声称为已测得玩家延迟。展示与关联由上游格式、共享合成日志和实际组件渲染验证。

## 启用方式

客户端下一次显式启动、连接或重新启动联机服务时，把引擎 `LogLevel` 设置为 -1、`MaxLogSize` 设置为 1 MiB。后台检查引擎是否立即退出，失败会返回可见错误。更新代码本身不会自动关闭当前正在运行的联机服务；已在运行的旧配置需手动重新启动联机服务后才产生心跳 RTT 日志。

## 前后端同步

- Rust IPC、前端类型、服务器诊断 DTO 均提供 `latencyMs`、`latencyUpdatedAt`、`latencyStale`、`latencySource`。
- `/api/p2p/config` 新增可选 `peerMetrics` 合约，标明 RTT、ms、30 秒时效和所需日志等级，兼容旧客户端。
- 新增鉴权管理接口 `POST /api/admin/p2p/inspect-log`，仅接受不超过 64 KiB 的手动日志片段；不落库、不自动上传客户端日志。
- 管理控制台「多源调度」增加对端 RTT 日志诊断，渲染对端名称时进行 HTML 转义。

## N01–N03 修复

1. 活跃配置必须同时匹配目标 UID、本地端口、远端端口和协议；同端口其他房间不会被误标。界面区分「配置已启用」和实际连接确认。
2. 房主生成分享码等待后台启动结果，失败不复制成功码；操作期间阻止重复点击并恢复按钮状态。
3. 游戏移除、清空同时处理 `config/lua/Disable`；清空保留第三方规则、错误计数与 AppList 同步。
