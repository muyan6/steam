## 签名密钥切换

旧报告中的签名私钥已删除，旧公钥加入服务端撤销名单，客户端信任公钥已更新。Git 历史仍包含旧文本，因此以**撤销旧密钥**而不是“秘密重新保密”作为修复依据。不要继续用旧私钥签发，也不要用仓库历史中的秘密恢复线上服务。

新的私钥只保存在开发机忽略目录 `server/data/license_ed25519_private.pem`，不随 Git 推送。对应公开公钥为 `src-tauri/src/license_verify.rs` 的 `DEFAULT_PUBKEY_HEX`。线上 PM2 需要安全配置与该客户端发行版对应的私钥；**不要在线上另生成一把随机私钥后直接用于已发布客户端**。

切换应先备份线上 `server/data` 与 `.env`，准备新版客户端安装包，再配套部署该签名密钥与新版客户端。既有 `license_keys.json` 设备绑定及有效期不需要删除或重置；客户端联网后重新获取新签名缓存。旧客户端的离线缓存继续由旧客户端判断，新版客户端不接受旧签名。此次源码提交和 Git 推送本身不代表线上服务或用户客户端已经完成切换。

自部署并同时构建自己的客户端时，可以在自己的完整源码目录执行：

```sh
cd server
node scripts/prepareDeployment.mjs --rotate-signing-key --sync-client-public-key
npm run build
cd ..
npm run tauri:build
```

其中轮换命令是显式迁移命令，不应在每次普通更新时重复执行。

## PM2

部署脚本先运行 `prepareDeployment.mjs`，检查/准备必需的 JWT 与签名文件；发现已撤销的旧密钥时中止，不自动以不匹配的密钥重启线上服务。仓库遗留的固定初始管理员密码会在预检中被替换，已独立改密的管理员凭据保留。随机初始密码保存在服务器本地 `.env`，不输出到构建日志。

```sh
cd server
node scripts/prepareDeployment.mjs
npm run build
pm2 restart ecosystem.config.cjs --update-env
curl -fsS http://127.0.0.1:1257/api/health
```

PM2 配置指定 `cwd`，显式读取本地 `.env`；更新使用配置文件重载，避免旧进程缓存环境覆盖新配置。健康检查失败时安装/更新脚本返回非零退出码。

Docker 用户先准备服务器本地 `.env`，Compose 显式加载该文件。私钥使用持久化的 `data` 目录或私钥环境变量注入，不使用源码默认密钥。

## 数据与接口兼容

- 管理员凭据、审计、通知、密钥及令牌等 7 个历史已跟踪的运行时文件解除跟踪，保留本机文件。旧服务端的数据目录需要继续备份；此次没有用占位密钥替换真实数据库。
- 现有客户端上报请求仍兼容；服务端返回 `accepted/rejected/queued`，未知设备先发送设备心跳。上报仅进入有界待核验索引，不把客户端提供的码值直接放进共享缓存。旧版混合来源缓存失去信任，权威查询重新填充新版本缓存。
- 邀请记录增加可选奖励状态、实际奖励天数及错误摘要；后台显示“待补发”。补发每分钟重试有限数量，实际授权文件内保存奖励幂等账本。历史记录的 `inviterDays=0` 无法区分终身卡免发与旧版失败，因此不盲目对历史 0 天记录补奖。
- 版本 DTO 的 `sha256` 传入更新 IPC；没有摘要的旧版本 DTO 继续兼容，提供非法摘要则明确报错。应在发行流程为安装包填写正确摘要。
